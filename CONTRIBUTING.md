# Contributing to FutraDay

FutraDay repositories are maintained with a bias toward small, testable, production-safe changes.

## Changes

- Start from the repository's default branch unless the repository documents another workflow.
- Keep pull requests focused on one problem or deliverable.
- Include tests or validation evidence for behavior changes.
- Never commit credentials, API keys, tokens, customer data, or local `.env` files.
- Call out database migrations, environment-variable changes, deployment changes, billing impact, and breaking changes explicitly.
- Preserve existing deployment and rollback paths unless the change intentionally replaces them.

## Pull requests

Describe what changed, how it was validated, and any deployment or operational impact. Link the relevant issue or task when one exists.

For security vulnerabilities, follow `SECURITY.md` rather than opening a public issue.

Repository-specific contributing instructions take precedence when present.
